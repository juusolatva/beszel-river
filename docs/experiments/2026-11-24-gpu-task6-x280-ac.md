# GPU prototype, Task 6 on the optimized CPU path: X280 on AC, Chrome and Firefox — 2026-11-24

**Result: the GPU backend still meets the
[keep threshold](../superpowers/plans/2026-11-13-gpu-prototype.md#task-6-measure-and-decide) in every
dense cell, in both browsers.** Callback work in the dense runs falls 69–76 % in Chrome and 57–67 % in Firefox.
The CPU reference is now the optimized path, with parts 1–2 Tasks 1–5 merged (`7deb629`), not the one the
[2026-11-17/18 runs](2026-11-18-gpu-task6.md) measured. Since then the CPU path has become 10–15 % cheaper in
Chrome's dense runs, while the GPU path stayed at about 1.5 ms. Every gated run passed occupancy parity, and every
final state matched its validation replay. These are AC runs on one laptop. Battery and phone checks on the optimized CPU path remain, and power is
still unmeasured.

## Frame cadence

Chrome had no missed display periods in any run; its frame-interval p95 was 16.7 ms throughout. Firefox
missed one period in all 86 runs (CPU, `dense-8000`, 960×640). Its interval median and p95 were
16.3 / 17.2 ms in every run on both backends: Firefox spreads its frame timestamps around the 60 Hz period
instead of quantizing them. Each measured minute still held 3,602–3,603 callbacks, as in Chrome. The GPU backend
does not change cadence on this laptop in either browser; the gain is CPU headroom.

GPU time is bimodal per run, never within a run; the medians above hide that, and the per-run values are
in the exports. Two changes from 2026-11-17 were not investigated:

- **960×640:** the GPU backend's GPU time rose from 1.4–2.1 to 2.0–2.7 ms per run, and its own
  simulation passes from 0.3 to 0.5 ms. This happened with Chrome 158 instead of 157, and on a harness that now
  includes Tasks 1–5. The callback cost on the CPU side did not rise.
- **Full screen:** in the heavy workloads (discovery, dense, rotation, schedule replay) the CPU path sat in
  its upper mode, about 5 ms, in 12 of 13 runs. On 2026-11-17 those runs split between 2.6–2.9 and
  4.0–4.3 ms.

The CPU path's p95 values of 13–15 ms appear in both sets and remain unexplained.
